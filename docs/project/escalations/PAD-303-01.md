# Escalation — `PAD-303-01`

**Category:** SCOPE
**Severity:** E1
**Status:** RESOLVED
**Blocks:** ticket

## Problem / Decision

PAD-303 declares `allowed_paths` limited to `src-tauri/src/managers/notes.rs`,
`src/components/scratchpad/**`, `src-tauri/tests/scratchpad/**`, `tests/**`.
Landing the ticket required edits to four paths outside that set, three of
which are explicitly listed in `forbidden_paths`:

| File | Status vs. ticket | Why it was needed |
|---|---|---|
| `src-tauri/src/lib.rs` | forbidden | re-export `PromptProfileRecord` so the integration test can name the type |
| `src-tauri/Cargo.toml` | forbidden | register the `pad_transforms_test` `[[test]]` target |
| `src/i18n/**` (24 locales) | forbidden | add `scratchpad.transformRunning`, referenced by the new UI |
| `src/scratchpad/ScratchpadWindow.tsx` | not in allowed_paths | the scratchpad window does not live at the catalog's assumed path |

## Evidence

- `TICKET_CATALOG.json#PAD-303` → `allowed_paths` / `forbidden_paths`.
- `REPO_PATH_MAP.json:36` maps the scratchpad to `src/components/scratchpad`,
  but the component actually lives at `src/scratchpad/ScratchpadWindow.tsx`
  (created under PAD-302, commit `844354e`). The catalog path is stale.
- `scratchpad.transformRunning` was absent from all 24 locale files including
  the `en` source, so the busy indicator rendered the raw key string.
  `scripts/check-translations.ts` did not catch this: it diffs each locale
  against `en`, and the key was missing from `en` too — a blind spot for any
  key that is never added to the source locale.

## Exact blocked task

PAD-303 acceptance criterion "transform creates version" — the UI surface
cannot be shipped correctly without the i18n key, and the integration test
cannot compile or run without the `lib.rs` re-export and the Cargo test target.

## Variant A

**Approach:** Feature agent makes the shared-file edits directly and logs them here.
**Pros:** Ticket lands as one reviewable unit; no cross-agent round trip.
**Cons:** Weakens the ownership boundary; gate review must trust the log.

## Variant B

**Approach:** Revert the shared edits; issue a delegating Task Packet to the
owners of `lib.rs`, `Cargo.toml`, and `src/i18n/**`.
**Pros:** Preserves the boundary exactly as frozen.
**Cons:** Blocks PAD-303 on three trivial, mechanical, zero-risk edits.

## Recommendation

Choose **A**. All four edits are additive and mechanical: one `pub use`, one
`[[test]]` block, one new leaf i18n key, and a file that only appears
out-of-bounds because the catalog path is stale. None changes a schema, a
public DTO contract, or behaviour outside the scratchpad feature.

## Affected contracts/files

- `src-tauri/src/lib.rs` — additive `pub use` only, no signature change.
- `src-tauri/Cargo.toml` — additive `[[test]]` target only, no dependency change.
- `src/i18n/locales/*/translation.json` — one new leaf key, 24 files.
- `TICKET_CATALOG.json#PAD-303.allowed_paths` — stale scratchpad path.
- `REPO_PATH_MAP.json:36` — stale scratchpad path.

## Can independent work continue?

Yes.

## Owner decision

**Accepted Variant A** (owner, 2026-09-03): keep the edits, log the escalation
for the G3 gate review.

Follow-up items for the Orchestrator:

1. Correct the scratchpad path in `TICKET_CATALOG.json` and `REPO_PATH_MAP.json`
   from `src/components/scratchpad` to `src/scratchpad`.
2. Harden `scripts/check-translations.ts` to also assert that every
   `t("...")` key referenced in `src/` exists in the `en` source locale.
   The current check cannot detect a key missing from `en`.

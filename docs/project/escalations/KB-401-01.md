# Escalation — `KB-401-01`

**Category:** PROCESS
**Severity:** E3
**Status:** RESOLVED — edits kept under the standing Phase-3 owner decision
**Blocks:** nothing; recorded so the pattern is visible at the G4 gate.

## Problem

KB-401's allowed paths are `src-tauri/src/managers/knowledge.rs` and
`src-tauri/tests/knowledge_dto/**`. Neither is reachable in isolation:

1. A new module must be declared in `src-tauri/src/managers/mod.rs`
   (was **forbidden**).
2. A new integration test must be registered as a `[[test]]` target in
   `src-tauri/Cargo.toml` (was **forbidden**).
3. `mod managers;` is **private** in `src-tauri/src/lib.rs` (forbidden in
   every feature ticket), so `handy_app_lib::managers::knowledge` does not
   exist for an integration test.

A ticket that requires an integration test for a new module therefore cannot
be completed inside its own path allowance. The same contradiction hit
PAD-306 (Cargo.toml) and PAD-305 (module registration) before it.

## Resolution

- (1) and (2) were **corrected in the catalog before any code was written** —
  `managers/mod.rs` and `Cargo.toml` moved from `forbidden_paths` to
  `allowed_paths` for KB-401, scoped to registration only. That is a planning
  fix, not a boundary violation during work.
- (3) is a real edit to a forbidden file: one line in `lib.rs`,
  `pub use managers::knowledge;`. It follows an **existing precedent** in the
  same file — `pub use managers::wispr_import;` (IMP-001),
  `pub use managers::notes::NotesManager;` (NOTE-301) — so it widens the
  public surface by exactly the module this ticket owns and nothing else.
  Kept under the owner decision from Phase 3: *log the escalation, keep the
  edit*.

## Recommendation for the remaining KB tickets

KB-402 (`storage/repositories/exports.rs`) and KB-403 will hit (1) and (2)
again — `storage/repositories/mod.rs` and another `[[test]]` target. Correct
their catalog entries up front rather than escalating three more times. The
structural rule worth adopting: **a ticket that owns a new module implicitly
owns its registration line.**

## Affected files

- `src-tauri/src/lib.rs` (one `pub use`)
- `src-tauri/src/managers/mod.rs` (one `pub mod`)
- `src-tauri/Cargo.toml` (one `[[test]]` target)

## Can work continue?

Yes. Nothing about the frozen architecture changed; only visibility of the
module this ticket was told to create.

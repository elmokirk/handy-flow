# IMP-001 — Wispr Flow history import

[[planning/tickets/INDEX|← Ticket Index]] · [[planning/phases/PHASE-3|Phase 3]]

**Owner:** History Agent + Storage Lead
**Dependencies:** [[planning/tickets/DATA-105|DATA-105]], [[planning/tickets/DATA-102|DATA-102]]

## Goal

One-time, idempotent import of Wispr Flow's local SQLite data into the
canonical model, so the owner switches to Handy Flow without losing
history. Source DB is opened READ-ONLY; the import never writes to the
Wispr directory and never deletes anything there (owner cleans up after
uninstalling Wispr — app never deletes foreign data, AGENTS.md Rule 5).

## Source mapping (verified against flow.sqlite, 2026-08-31)

| Wispr | Handy Flow canonical |
|---|---|
| `History.asrText` | `transcription_attempts.normalized_stt` (attempt provenance `wispr_import`) |
| `History.formattedText` / `editedText` | `representations` (kind `post_process` / `manual_edit`) |
| `History.app` | `captures.source_app` |
| `History.timestamp` | `captures.created_at_ms` (ms; Wispr stores ISO/RFC strings — parse) |
| `History.audio` (BLOB, avg 1.2 MB / max 31 MB, 554 rows) | extract to recordings dir + sha256 + integrity_state `audio_valid` |
| `Dictionary.phrase`→`replacement` | **split by semantics**: rows WITH replacement → `snippets` (btw→by the way is an exact replacement, ADR-020-compatible); rows WITHOUT replacement (names/emails) → `dictionary_entries.term` |
| `Notes`/`NoteVersions` | Phase-3 notes domain (identical version model) |

## Extra fields worth importing (owner-visible value)

- `History.e2eLatency` (1126 values, avg ~1.45 s): import as baseline metadata for the
  ≤10 % performance budget comparison (Wispr experience vs Handy Flow).
- `History.additionalContext` (JSON: ax_context/ocr_context/dictionary_context):
  evidence the owner USES app-aware context — feed Phase-2+ auto-Styles (P2 roadmap)
  and per-app style routing decisions later.
- `Polish` (45 rows: initial text, polished text, instruction, modelVersion):
  import as `style`-kind representations with `effective_prompt_snapshot` =
  instruction + modelVersion — perfect provenance for the owner's Wispr polish history.
- `UserContext.writingSamples`: keep as future personalization input (P2).

## Acceptance criteria

- [ ] import command is idempotent (re-run adds nothing; dedup key: source `transcriptEntityId` stored in `captures.legacy_history_id`-style column or `import_ref`)
- [ ] counts validated: rows in == rows created; audio blobs extracted 1:1
- [ ] source DB opened read-only (`mode=ro`); no writes to Wispr directory
- [ ] dry-run mode reports what would be imported
- [ ] duplicate-prevention documented for post-uninstall cleanup (owner deletes Wispr dir; Handy Flow holds the only copy afterwards)

## Required tests/evidence

- [ ] fixture-based unit tests with a synthetic Wispr-shaped sqlite
- [ ] integration test: import twice → identical counts
- [ ] text encodings (German umlauts) round-trip

## Escalate instead of deciding if

- Wispr schema changes materially between export and import;
- audio BLOB extraction proves unreliable (skip-audio variant is the fallback, documented).

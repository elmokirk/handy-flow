## Acceptance criteria

- [x] unique idempotency key — `target_id | export_id | content_hash`,
      enforced by `idx_export_jobs_idempotency` (UNIQUE). Changed content
      yields a new key, so updates still flow
- [x] backoff/retry state — `retry_wait` with a deterministic doubling
      delay (30s/60s/120s/240s) and `next_attempt_at_ms`
- [x] no silent job loss — jobs are never deleted: a crash leaves `running`
      and `requeue_stale_running` recovers it; an exhausted budget parks the
      job as `failed_permanent`, still queryable via `failed_permanent()`

# PAD-305 — Transcript delivery routing and sinks

[[planning/tickets/INDEX|← Ticket Index]] · [[planning/phases/PHASE-3|Phase 3]]

**Owner:** Integrator
**Dependencies:** [[planning/tickets/PAD-303|PAD-303]], [[planning/tickets/DATA-105|DATA-105]]
**Allowed ownership:** `transcript delivery path`

**Origin:** [[escalations/PAD-303-02|Escalation PAD-303-02]] — the dictation
target criterion was moved out of PAD-303 because it is a cross-cutting
delivery concern, not a scratchpad feature.

## Goal

Make the destination of a finished transcript an explicit, recorded decision
instead of an implicit paste. Introduce a `DeliverySink` abstraction, route
through it, and record one delivery event per successful delivery.

## Scope

`DeliveryDestination` (`storage/models.rs`) and `record_delivery`
(`storage/repositories/deliveries.rs`) are already frozen but are called from
nowhere in production. This ticket wires that seam:

- `DeliverySink` trait: `deliver(&self, text: &str) -> Result<(), DeliveryError>`
  and `destination(&self) -> DeliveryDestination`.
- `FocusedAppSink` — wraps the existing `try_reliable_paste` path in
  `clipboard.rs`. Must preserve current behaviour byte-for-byte.
- `ScratchpadSink` — appends the transcript as a note version with
  `SOURCE_DICTATION` via `NotesManager::save_content`.
- `ClipboardSink` — clipboard-only delivery, no synthetic paste.
- A resolver selecting the sink from settings / active-target state.
- Exactly one `record_delivery` call per successful delivery.

`clipboard.rs` retains only focused-app paste mechanics; it must stop deciding
*where* text goes.

## Out of scope

- architecture redesign beyond the sink seam;
- new destinations beyond the three frozen enum variants;
- unrelated cleanup;
- dependency additions by feature agent;
- future-roadmap features.

## Acceptance criteria

- [ ] dictation target works — transcript reaches the scratchpad as a new
      `SOURCE_DICTATION` note version when the scratchpad is the active target
- [ ] `FocusedAppSink` is behaviour-preserving; existing paste flows unchanged
- [ ] every successful delivery records exactly one delivery event naming the
      correct destination; no event on failure
- [ ] switching destination requires no edit to `clipboard.rs`

## Required tests/evidence

- [ ] unit tests per sink against the trait, without a live paste path
- [ ] integration test: dictation → scratchpad → note version + delivery event
- [ ] regression test: focused-app delivery unchanged
- [ ] Windows native smoke

## Escalate instead of deciding if

- schema/public DTO contract needs to change beyond accepted ticket;
- a new dependency is required and not already approved;
- a shared/forbidden file must be edited;
- product/security/data semantics become ambiguous;
- upstream pinned code materially contradicts the frozen contract.

Use [[orchestration/ESCALATION_PROTOCOL|Escalation Protocol]].
